# Runtime 性能验证

此轮优化范围是隐藏时暂停无用工作、减少详情深拷贝、统一 Codex 状态获取。不更改原生窗口动画、材质、预热或隐藏复用；不减少日志解析范围，不改变模型关联规则。

## 2026-11-10 实测

旧版为 preview-v13（`0801a65`），新版为 preview-v14（`cdb8f9d`）。完成实现和回归后串行采样，表格采用无并行编译或回归的完整三场景复测；每场景约 31 秒（含采样间隔开销），20 逻辑处理器，均为 8 个应用及 WebView2 进程。数字为本轮观测值。

| 场景 | 旧版整机 CPU | 新版整机 CPU | 旧版私有驻留 MiB | 新版私有驻留 MiB |
| --- | ---: | ---: | ---: | ---: |
| 隐藏，日志持续追加 | 1.10% | 0.21% | 491.8 | 248.8 |
| 侧栏展开 | 0.99% | 1.26% | 730.8 | 636.4 |
| Inspector 打开 | 1.27% | 1.27% | 947.9 | 804.5 |

隐藏场景 CPU 下降约 81%，私有驻留内存下降约 49%；展开侧栏与 Inspector 的私有驻留内存分别下降约 13% 和 15%。隐藏时进程树 I/O 读计数为 75.26 → 0.12 MiB，写计数为 55.79 → 0.13 MiB。前台 I/O 没有下降，侧栏 CPU 本轮上升，Inspector CPU 基本相同，不能宣称前台 CPU 已改善。列表遍历、详情请求与界面刷新尚未做下一阶段的增量化优化。

原始报告位于 `target/runtime-perf-MuuJvB/report.json`（旧）与 `target/runtime-perf-2HToSS/report.json`（新）。两份 fixture 均为 1,387,102 字节初始目标日志、36 个目录文件、每 500ms 追加 2 KiB 文本。日志和数值均来自合成测试，无真实对话正文。测试版 SHA-256：`C8FC618347DC9CC8F7F391E3B3F2CCAA52F2491F9EB131B2216DCDAAC5D7EB97`。

另用 `30 sidebar` 参数单独复测侧栏，避免前置隐藏场景的积累：Rust 主进程约 31 秒内 CPU 时间为 2.28 → 1.50 秒，私有驻留为 30.4 → 22.9 MiB。整个进程树 CPU 为 1.48% → 1.36%，但新版结束时出现额外进程（9 vs 8），该组总内存与 CPU 不作为严格等进程集合对比；报告位于 `target/runtime-perf-mxsSPA/report.json` 和 `target/runtime-perf-BF4Qem/report.json`。两种测试表明，后端复制开销降低，但前台总占用受 WebView、GPU 与场景历史影响，尚不能得出稳定的整树前台 CPU 降幅。

## 可复现负载

`node scripts/measure-runtime-perf.cjs <绝对 EXE 路径> [每场景秒数，默认 30]` 启动自己的实例。先退出用户实例，再串行测试旧版和新版，测量期间不运行编译和其他回归。脚本使用独立 `CODEX_HOME`、APPDATA、LOCALAPPDATA 和 WebView profile；不读取真实会话，不修改用户配置。调试接口只绑定 loopback，测完关闭自己创建的进程。产物与报告留在忽略的 `target/runtime-perf-*`。

固定 36 份会话文件，目标会话预置 50 回合、1,000 条事件记录（受产品 800 条保留上限约束），工具参数 1 KiB、结果 2 KiB。预热 10 秒后每 500ms 追加 2 KiB 助手文本。依次测隐藏、侧栏、Inspector，各场景读取进程树起止计数；CPU 按逻辑处理器数归一化。最终内存为每场景结束值，不是峰值。Inspector 阅读固定工具记录，追加发生在同一文件，测试无需在线模型。

可追加 `hidden` / `sidebar` / `inspector` 参数单独测某一场景。CPU/I/O 增量只统计起止两次采样中共同存活的进程；出现进程变化时脚本会标记并告警。未捕获两次采样之间启动又结束的进程，测瞬时峰值或完整短命子进程成本需要另用连续采样或系统级追踪。

这是合成持续写入负载，包含 WebView 调试连接，不能把内存绝对值当成正常桌面空闲占用。比较对象应为同协议测试的前后版本；真实环境下约 31 秒的 v13 测量（私有工作集约 129 MiB、CPU 约 0.62%）作为独立观察，不能直接与合成负载对比。进程 I/O 计数包含缓存和管道，不等于物理磁盘流量。跨场景保留进程和既有页面，因此后一个场景内存还受到前面场景的影响；短测不能判定泄漏。

## 功能回归

详情存储改为共享不可变原始 JSON 和独立的模型关联覆盖层，快照及标题克隆不再深拷贝正文；镜像更新采用写时复制，详情 IPC 才合并序列化，两种来源和原始内容保持兼容。Codex 状态由单个后端采样器每 2 秒读取，命令只读缓存；相位变化直接更新托盘并推送给胶囊，隐藏胶囊不绘制，显示时读取缓存。清除状态会同步更新缓存和两种显示模式，不再叠加第二个轮询周期。

- `node scripts/test-hidden-work.cjs`：隐藏胶囊不查询状态或刷新时钟，显示后恢复。
- `cargo test --lib`：解析、模型关联、历史链、窗口和动画单元回归。
- `node scripts/test-tray-native.cjs --release --display --runtime`：真实 WebView2、隐藏暂停及重新展开追平、原始内容、Inspector、快速反向动画与几何边界。
- `node scripts/test-tray-ui.cjs`：深浅主题、DPI、选择器、Inspector、安全正文和滚动状态。

性能测试使用版本号为 0.2.1 的预览构建：65 项 Rust 测试通过（1 项本机审计按设计忽略）、29 项概述测试通过、隐藏工作/状态订阅专项通过、36 组界面场景通过，Release 原生窗口回归通过。上述改动纳入 v0.2.2；表中的占用数字仍对应原预览二进制，不将版本号更新后的构建冒充重新测量的样本。
